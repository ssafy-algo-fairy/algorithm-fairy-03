# [Gold II] 가운데를 말해요 - 1655

[문제 링크](https://www.acmicpc.net/problem/1655)

## 💡 고민 과정 및 시행착오

### 1. 첫 번째 접근: 절반을 버리는 우선순위 큐
* **아이디어:** 어차피 중간값보다 작은 숫자는 필요 없다고 생각하여, 하나의 `PriorityQueue`를 쓰고 짝수 번째 입력마다 큐에서 가장 작은 값을 `poll()`로 버리는 방식을 시도함.
* **실패 원인:** 나중에 중간값보다 더 작은 숫자들이 대량으로 들어올 경우, 전체적인 중간값이 낮아져야 함. 하지만 이미 작은 값들을 큐에서 영구적으로 삭제해 버렸기 때문에 정확한 중간값을 추적할 수 없는 치명적인 반례가 존재했음.

### 2. 두 번째 접근: TreeSet 활용
* **아이디어:** 삽입할 때마다 자동으로 정렬되는 `TreeSet`을 사용해 중간 위치에 있는 값을 찾으려 함. 삽입 자체는 $O(\log N)$이므로 효율적일 것이라 예상함.
* **실패 원인:** Java의 `TreeSet`은 이진 탐색 트리 기반이지만, 내부 원소에 인덱스로 접근하는 `get(index)` 기능을 제공하지 않음. 따라서 중간값을 찾으려면 `Iterator`로 처음부터 절반까지 순회해야 하며, 이 탐색에 $O(N)$이 소요됨. 결과적으로 총 시간 복잡도가 $O(N^2)$이 되어 제한 시간(0.1초) 내에 통과할 수 없어 **시간 초과(TLE)**가 발생함.

### 3. 최종 해결책: 2개의 우선순위 큐 (Max Heap & Min Heap)
* **아이디어:** 버려지는 값 없이 모든 값을 유지하되, **중간값 이하의 숫자들은 최대 힙(Max Heap)**에, **중간값보다 큰 숫자들은 최소 힙(Min Heap)**에 나누어 담는 정석적인 방법을 사용.
* **시간 복잡도:** 값을 삽입하고 힙을 재정렬하는 데 걸리는 시간만 소요되므로 $O(N \log N)$으로 0.1초 안에 충분히 통과 가능.
